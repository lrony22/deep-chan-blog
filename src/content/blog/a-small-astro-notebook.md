## 从文字开始，而不是从功能开始

这是一篇示例技术笔记。它用一间「文字小屋」来理解静态博客：Markdown 是纸页，布局是书架，链接把读者带到想看的地方。

个人博客最常发生的事情，是有人打开一个地址，读完一篇文章。围绕这件事设计，很多选择就会变得简单。我们需要清晰的排版、可靠的链接，以及快速打开的页面。

Astro 可以在构建时把文章转成 HTML。访客浏览一篇普通文章时，不需要先等待一个完整的前端应用启动。

## 给内容一个清晰的家

把文章放在独立目录，元信息写在文件顶部。标题、日期和标签都属于内容本身，而不是散落在页面模板中的特殊判断。

```yaml
---
title: 一封新的来信
description: 今天想记下的一件小事。
pubDate: 2026-10-24
tags: [日常, 好奇心]
draft: false
---
```

内容集合会在构建时检查这些字段。少写日期、写错类型时，尽早得到明确反馈，比等页面上线后再发现问题更安心。

### 只给需要的地方一点 JavaScript

主题切换、文章搜索和代码复制需要交互，但正文不需要。把脚本集中在这些小功能上，可以让结构更容易理解。

```js
const saved = localStorage.getItem('blue-mode') || 'auto';
const systemIsDark = matchMedia('(prefers-color-scheme: dark)').matches;

document.documentElement.dataset.theme =
  saved === 'auto' ? (systemIsDark ? 'dark' : 'light') : saved;
```

实际项目还需要处理浏览器禁止存储的情况，并监听系统偏好变化。小功能做完整，比单纯把代码写短更重要。

## 让路径也经得起搬家

部署到仓库子目录时，`/about/` 和 `/deepseek-blog/about/` 不是同一个地址。图片、搜索索引和 RSS 同样需要考虑这个区别。

因此，路径应当从一个统一入口生成，而不是在每个组件里手写。

| 需要检查的地方 | 原因 |
| --- | --- |
| 导航和文章链接 | 确保从任意页面都能继续浏览 |
| 图片与字体 | 避免部署后出现空白或回退 |
| 搜索与 RSS | 数据地址也会受子路径影响 |

## 小屋不必一次盖完

先把阅读、写作和导航这三件事做顺。等真正遇到新的需求，再添一扇窗、一盏灯，或一张新的书桌。

一个轻盈的博客，应当让人更想写下一篇文章。
